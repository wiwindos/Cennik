BACKGROUND KEYS

Запуск: BackgroundKeys.exe. Установка и Python не нужны.
Требуется Windows с .NET Framework 4.x (есть в Windows 10/11).

1. Откройте нужные приложения и нажмите «Обновить».
2. Отметьте галочками одно или несколько окон. Поиск фильтрует список;
   ранее отмеченные окна остаются выбранными, даже если скрыты фильтром.
   «Снять выбор» очищает весь выбор, «Выбрать все» отмечает видимые строки.
3. Для смены клавиши кликните её поле и нажмите нужную клавишу.
   По умолчанию: 3 и 4 верхнего цифрового ряда. Поддерживаются одиночные
   клавиши, включая буквы, стрелки, F1–F24 (кроме F8) и NumPad.
   Сочетания Ctrl/Alt/Shift не поддерживаются. F8 зарезервирована для стопа.
4. Укажите диапазон задержки. По умолчанию 0,30–0,80 секунды.
   При равных границах задержка фиксированная; иначе случайная.
5. Нажмите «Старт». Последовательность: 3 → 4 → 3 → 4…
   Каждая клавиша отправляется всем выбранным окнам в одном цикле.
   Отправка последовательная через очереди Windows, без гарантии
   одновременной обработки до миллисекунды каждым приложением.
6. «Стоп» или глобальная F8 останавливает отправку. Если F8 уже занята,
   программа сообщит об этом рядом с кнопками; кнопка «Стоп» работает.

Таймер показывает длительность текущего запуска, после стопа сохраняет
результат, при следующем старте сбрасывается. «Цикл» — отправка одной
клавиши группе окон. Число нажатий учитывает каждое окно отдельно.
Клавиша удерживается примерно 35 мс. Задержка задаётся между началами
нажатий, а не добавляется к удержанию. Точность зависит от нагрузки Windows.
Настройки меняются после остановки. Автозапуска отправки нет.

Пункт «Отправлять в дочерний элемент с фокусом» помогает приложениям,
в которых клавиши принимает поле ввода, а не главное окно. Если приложение
ожидает клавиши в главном окне, снимите галочку и проверьте снова.
Утилита не активирует окна и не переводит на них системный фокус.

СОВМЕСТИМОСТЬ

Отправка использует WM_KEYDOWN/WM_KEYUP через PostMessage. Это сообщения
окну, а не физическая клавиатура. Некоторые игры, приложения с Raw Input /
DirectInput, защищённым вводом, а также свёрнутые приложения могут их
игнорировать. Успешная постановка сообщения в очередь не подтверждает,
что приложение выполнило действие. Счётчик считает отправленные сообщения.
Обхода ограничений, драйверов и внедрения в процессы нет.

Windows запрещает отправлять сообщения процессу с более высокими правами.
Если целевое приложение запущено администратором, запустите утилиту
с такими же правами. При ошибке постановки сообщения утилита останавливается.
Закрытые окна исключаются из запуска; если закрыты все — работа завершается.
При остановке и закрытии утилиты отправляется отпускание текущей клавиши.

СБОРКА И ПРОВЕРКА

Исходники: BackgroundKeys.cs и SelfTest.cs.
Пересборка в PowerShell:
  powershell -NoProfile -ExecutionPolicy Bypass -File .\build.ps1

Самопроверка (только собственные скрытые тестовые окна):
  .\BackgroundKeys.exe --self-test .\self-test.txt
Результат и код возврата доступны после завершения процесса.

Документация API:
https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-postmessagew
https://learn.microsoft.com/en-us/windows/win32/inputdev/wm-keydown
