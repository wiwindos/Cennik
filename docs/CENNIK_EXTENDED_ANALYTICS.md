# Лёгкая и расширенная аналитика

После новых данных автоматически рассчитываются включённые лёгкие стратегии:
аукцион → NPC, NPC → аукцион, покупка → распыление и простой крафт.
Историческая скидка, если её включили отдельно, также остаётся в автоматическом наборе.

Цепочки крафта и крафт → распыление запускаются из «Возможности → Расширенная аналитика»
кнопкой «Рассчитать цепочки и распыление». Можно выбрать профессию или до 100 ID готовых
предметов. Пустые поля означают весь доступный набор. Настройки стратегий действуют и здесь:
отключённый модуль не рассчитывается.

Показываются подготовка, этап и прошедшее время. Сообщение о работающей аналитике видно
в других разделах. По завершении появляется уведомление и новые возможности.
Новый расширенный расчёт заменяет предыдущую расширенную подборку целиком, в том числе
при выборе профессии или ID; лёгкие результаты сохраняются.

Тяжёлая аналитика выполняется отдельным процессом по неизменяемому входному срезу.
Процесс не открывает живую DuckDB и не занимает исполнитель приёма Worker.
Сканы сначала сохраняются и подтверждаются, автоматический расчёт ставится отдельно.
Изменения нескольких источников объединяются в ожидающий лёгкий расчёт.

При чтении рецептов принадлежность последнему снимку профессии проверяется в SQL до
загрузки составов в Python. Старые почасовые копии больше не разворачиваются целиком.
Правила выбора по рынку, времени источника, неоднозначным версиям и неполным составам
сохранены; компоненты загружаются только для выбранных версий.

Предыдущая расширенная подборка сохраняется при автоматических обновлениях. Дата её
исходного среза остаётся прежней. После изменения данных или настроек показывается
«Расширенный расчёт устарел». Планирование закупки, создание массовой проверки и прямой
экспорт устаревшей расширенной возможности требуют нового расширенного расчёта.
Публикация лёгких и расширенных результатов сериализована транзакцией, чтобы параллельное
завершение не теряло результаты другого расчёта. Существующие задания сохраняют свои ссылки.

Защитные пределы: один расширенный процесс на рынок, входной файл до 48 МБ, результат до
32 МБ, время до 20 минут. Контроллер раз в 250 мс проверяет RSS процесса: предел 384 МиБ.
На Linux также проверяется свободный запас общего cgroup (96 МиБ до жёсткого лимита).
Это наблюдаемые программные ограничения, а не отдельная жёсткая квота ядра для дочернего
процесса. При превышении процесс останавливается с понятным сообщением; предыдущая
публикация остаётся доступной. При перезапуске незавершённый расчёт помечается прерванным.

Диагностика находится в `extended-analysis/state.json`, `progress.json` и `worker.log`
в каталоге рынка. Временные `input.json` и `result.json` удаляются после завершения.
При аварийном завершении они могут остаться до следующего запуска расчёта.

API владельца/пользователя хаба: `GET /api/v2/extended-analysis`,
`POST /api/v2/extended-analysis` с JSON `{ "profession": "", "item_ids": [] }`.
Оба маршрута наследуют авторизацию выбранного рынка. Worker, Collector и аддон
обновлять для этой функции не требуется.
