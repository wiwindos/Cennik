# Хранение результатов расчёта

Полные возможности сохраняются только для опубликованного расчёта каждого рынка.
Возможности, используемые заданиями аддона и планами, закрепляются отдельно.
История запусков остаётся: настройки, время, ошибки, показатели и краткая диагностика.
Старые подробные результаты не используются как кэш после удаления возможностей.

Ротация выполняется в одной транзакции с публикацией нового результата.
Неудачный расчёт сохраняет предыдущую публикацию. Таблицы учёта, задания, источники,
настройки и игровые названия не удаляются. Архивы сканов, Parquet и рыночная DuckDB
этой ротацией не изменяются.

## Первое обслуживание большой базы

Для существующей большой SQLite используется отдельная офлайн-пересборка:

1. Собрать сервер с новым кодом и остановить только Cennik.
2. Выполнить checkpoint SQLite; другие соединения должны быть закрыты.
3. `python -m cennik.storage.compact --source /data/markets/ID/state.sqlite --target /data/markets/ID/state.compact.sqlite --report /data/markets/ID/logs/retention-compaction.json --checkpoint`
4. Дождаться `state=verified`. Инструмент проверяет содержимое всех остальных таблиц
   по количеству и SHA-256, сохранность текущих возможностей, связи и целостность SQLite.
   Исходный файл остаётся на месте. Новый файл ограничен 256 МБ.
5. Переключить файлы при остановленном приложении, сохранить исходный до проверки запуска.
6. Запустить Cennik и проверить авторизацию, текущие возможности, задания и настройки.
   После успешной проверки удалить прежний файл с устаревшими результатами.

Обычный `VACUUM` большой базы при почти заполненном диске не используется.
Пересборке требуется место только под небольшой проверенный результат.
