# Полная серверная версия Cennik

Архив `dist/CennikServer.zip` подготовлен для самостоятельного развёртывания.
На сервере работают стратегии, расчёты партий, снайпер, массовые проверки, учёт,
производственные заказы и сбор данных. Игровые действия выполняются аддоном и
подтверждаются игроком. Сервер не подключается к памяти WoW и не нажимает кнопки.

## Состав

- **Cennik Server**: закрытый веб владельца, аналитика и хранение, управление
  серверами, рабочими ПК и сборщиками.
- **CennikWorker.exe**: твои аукционер и крафтеры. Приватный двусторонний обмен
  заданиями, массовыми проверками, производством и финансовыми отчётами.
- **CennikCollector.exe**: сторонние участники. Только публичные наблюдения.

Это три разных роли и разные ключи. Ни Collector, ни Worker не получают ключ
владельца и доступ к его веб-API. Worker видит только назначенные ему персонажи.
Коллекторский приёмник находится под `/collect`, закрытый обмен — `/bridge/v1`.

## Изоляция серверов и источник AHledger

При первом запуске создаётся отдельный профиль **PvP · Альянс · EU**. Его внутренний
ID не зависит от будущего имени игрового сервера. Пока имя не известно, список
имён пуст; сбор и игровые задания блокируются до привязки владельцем.

В панели можно создавать рынки любых поддерживаемых регионов и обеих фракций.
У каждого свои базы, архивы, задания, правила снайпера, учёт и заказы:
`markets/<стабильный ID>/`. Переименование метки не переносит данные.
Фракция, регион и тип созданного профиля неизменны: для других нужен новый профиль.
Одинаковые имена в разных регионах допустимы. Сборщику лучше выдавать ключ,
закреплённый за конкретным профилем. Неоднозначная привязка блокируется.

**AHledger выбирается только для одного профиля.** Его код задаётся отдельно от
внутреннего ID, например `forever.pvp.alliance.eu`. Запросы остальных профилей
блокируются, автоматический обход всех серверов отсутствует. Регион и фракция
кода источника должны соответствовать профилю. Автообновления по умолчанию выключены.
Архив источника сохраняет исходное имя рынка; аналитика использует внутренний ID.

Старые US-профили на исследовательском ПК не изменяются и автоматически не
переносятся. Сервер требует отдельную папку. Не указывайте `data/cennik-next`.

## Установка на Linux без Docker

Нужны Python 3.12+ для сервера, Caddy или другой HTTPS reverse proxy и отдельный
пользователь ОС для приложения. Команды ниже рассчитаны на Python 3.12 и пути
из приложенного systemd unit. Docker и существующие Compose-конфигурации не меняются.

1. Распаковать `CennikServer.zip` в `/opt/cennik`.
2. Создать пользователя `cennik` и установить окружение:

```sh
cd /opt/cennik
python3.12 -m venv venv
venv/bin/python -m pip install -r requirements.server.lock.txt
venv/bin/python -m pip install --no-deps .
```

3. Сгенерировать ключ владельца:

```sh
/opt/cennik/venv/bin/python -c 'import secrets; print(secrets.token_urlsafe(48))'
```

4. Скопировать `deploy/cennik-server.env.example` в `/etc/cennik/server.env`, заполнить
   `CENNIK_OWNER_KEY` и **точный внешний адрес** `CENNIK_PUBLIC_ORIGIN=https://ваш-домен`.
   Права файла — 600. Ключ не передавать игровым приложениям.
5. Скопировать `deploy/cennik-server.service` в `/etc/systemd/system/`. Unit ожидает
   пользователя/группу `cennik`, запускает приложение от него, хранит данные в
   `/var/lib/cennik-server` с правами 700. При других путях отредактировать unit.

```sh
sudo systemctl daemon-reload
sudo systemctl enable --now cennik-server
sudo systemctl status cennik-server
sudo journalctl -u cennik-server -n 100 --no-pager
```

Внутренний HTTP слушает только `127.0.0.1:8770`. Проверка:

```sh
curl --fail http://127.0.0.1:8770/healthz
```

6. В `deploy/CennikServer.Caddyfile` заменить `{$CENNIK_DOMAIN}` на настоящий домен
   либо задать эту переменную в окружении Caddy. Домен должен указывать на VPS,
   входящие 80/443 должны быть доступны. Подключить файл к конфигурации Caddy,
   проверить её командой `caddy validate --config <путь>` и перезагрузить Caddy.
   Порт 8770 наружу не публикуется.

Приложенный конфиг передаёт запросы в Cennik и ограничивает тело 64 МБ. Основания:
[request_body](https://caddyserver.com/docs/caddyfile/directives/request_body),
[reverse_proxy](https://caddyserver.com/docs/caddyfile/directives/reverse_proxy).
Параметры unit: [systemd.exec](https://www.freedesktop.org/software/systemd/man/latest/systemd.exec.html).

**Один процесс приложения, один worker Uvicorn.** CLI держит файловую блокировку
всей серверной папки; не запускайте второй экземпляр поверх неё. Расчёты разных
рынков ограничены одной одновременной аналитикой, обмен и приём имеют свои очереди.

## Первый вход и подключение игроков

Открыть внешний HTTPS-адрес, войти ключом владельца. Сессия — HttpOnly/SameSite
cookie, до 12 часов; выход и перезапуск сервера делают её недействительной.
Сторонний Origin не может менять настройки. Ключи не помещаются в URL.

1. В профиле PvP EU указать точное имя из `GetRealmName()` после открытия игры.
   При необходимости добавить несколько известных вариантов имени.
2. Проверить выбранный код AHledger. Он один на весь сервер; обновления включаются
   в настройках полного Cennik нужного рынка.
3. Создать рабочий ПК: роль, имя персонажа, сервер и необязательная папка аккаунта.
   Первым должен быть зарегистрирован аукционер, затем можно добавлять крафтеров.
   Несколько персонажей одного ПК можно зарегистрировать одним ключом.
4. Передать своим ПК адрес корня сервера и **ключ Worker**. Сторонним сборщикам —
   адрес `https://ваш-домен/collect` и **ключ Collector** нужного рынка.
5. Через «Открыть полный Cennik» перейти к прежним разделам. Там рассчитываются
   стратегии, публикуются задания, создаются массовые проверки и заказы крафтерам.
   Локальные пути игры на VPS не задаются. Синхронизация означает ожидание следующего
   соединения Worker; оно доставит адресный импорт в игру.
6. В разделе «Сборщики» проверять участников и подтверждать аукционистов нужного
   рынка. Неизвестный тип блокируется, межфракционные сканы остаются отдельным архивом.

## Доставка и сохранность

Collector пишет публичную надёжную очередь; основной сервер сохраняет оригинал
и происхождение по участнику. Полные сканы проверенного рынка поступают через
сохраняемую очередь в соответствующее рабочее пространство. Снимки не складываются
в суммарный объём рынка: рабочая книга заменяется одним полным актуальным снимком.
Неопределённый контекст остаётся в архиве, без обновления цен. Рецепты и результаты
распыления сохраняются как наблюдения и не заменяют автоматически справочник правил.

Worker хранит неподтверждённые приватные отчёты на игровом ПК. Каждому обмену
назначаются последовательность и канонический хеш; потеря ответа допускает повтор
без повторной операции. Сервер использует тот же проверенный пайплайн, что локальная
версия: задания, массовые отчёты, FIFO-учёт и производство. Ответ содержит отдельные
подтверждения и адресные импорты. Игра применит их после `/reload` или нового входа.

Отозванный ключ не выполняет новый обмен. Участник не может отправить отчёты за
другого назначенного персонажа или читать чужой импорт. Пауза/выход локального
приложения не выполняют действий в WoW и не меняют SavedVariables.

## Резервное копирование и обновление

Полная папка `/var/lib/cennik-server` содержит каталоги рынков, базы, публичный
архив, очередь пересылки, рабочие клиенты, приватные отчёты и ключевые хеши.
Для консистентной общей копии остановить `cennik-server`, скопировать папку целиком,
затем запустить. Хранить её отдельно от раздаваемых приложений.

Кнопка резервного копирования полного Cennik сохраняет отдельный рынок; она не
заменяет общую копию всего сервера. Перед обновлением сохранить серверную папку,
остановить процесс, установить новый код/зависимости и запустить снова. Исследовательский
ПК использует отдельные базы и не синхронизирует их автоматически с рабочим сервером.

## Нагрузка и оставшиеся проверки

Подготовлен отдельный стенд `tools/benchmark_server.py`: импорт синтетического
полного скана и работа включённых стратегий. **Только новая пустая папка**, например:

```sh
PYTHONPATH=src venv/bin/python tools/benchmark_server.py --root /var/tmp/cennik-load-new --lots 10000 100000 500000 1000000
```

Он сохраняет время импорта, время аналитики и пиковую память Python. Память DuckDB,
RSS всего процесса, диск, очередь при одновременных клиентах и задержку HTTP нужно
измерить отдельно на будущем VPS. Это часть оставшегося нагрузочного плана:
100k/500k/1m лотов и 10/50/100 одновременно отправляющих участников. Тест не доказывает
готовность конкретного VPS без измерений на нём.

Проверены временный сервер, браузер, разделение ролей и рынков, приватный обмен,
массовые проверки и производство. Публичный VPS этой работой не развёрнут, HTTPS
с реальным доменом и API настоящего Forever проверяются после установки пользователем.

## Локальный серверный стенд Windows

```powershell
$env:CENNIK_OWNER_KEY = '<отдельный случайный ключ минимум 32 символа>'
.\venv\Scripts\python.exe -m cennik.server --root outputs\my-server-test --origin http://127.0.0.1:8770
```

Можно использовать `start_server.cmd` с той же переменной окружения. Это серверный
режим на отдельной папке, обычный `start_cennik.cmd` продолжает запускать локальную
исследовательскую версию на 8766.
