# Рядом с ценой NPC

Раздел в боковом меню показывает одну строку на предмет: минимальную цену за штуку
в книге предложений обычного аукциона и цену продажи этой штуки NPC.
Минимум определяется по отношению полного выкупа к размеру стака, включая свои предложения.
В строке также показаны суммарное предложение предмета, дата скана и источник NPC-цены.

Наценка: `(минимальная цена аука / цена продажи NPC − 1) × 100%`.
Huge Emerald за 1 золото 3 меди при NPC-цене 1 золото имеет наценку **+0,03%**
и разницу **+3 меди за штуку**. Отрицательное значение означает цену ниже NPC.
Это сравнение цен, а не прибыль от продажи NPC или рекомендация выкупить весь стакан.

Диапазон наценки задаётся полями «от» и «до»; пустое поле снимает соответствующее ограничение.
По умолчанию верхняя граница +10%, нижняя не ограничена. Настройки сохраняются в браузере.
Начальная сортировка — по близости к NPC (модулю наценки). Доступны также наценка,
минимальная цена аука, NPC-цена, объём предложения и название, в обоих направлениях.
По заголовкам таблицы можно менять сортировку. Есть поиск по названию/ID,
ограничение возраста скана и страницы по 50 предметов.

Галочка «Скрыть нестакаемые» оставляет предметы с подтверждённой стакаемостью:
размер стака в справочнике больше единицы, в полном скане есть стак больше одной штуки
или API подтвердил тип commodity. Сам по себе тип не-commodity не доказывает отсутствие стака.
Одиночное предложение стакаемого материала остаётся; количество отдельных лотов не влияет
на отбор. Предметы с неизвестной стакаемостью при включённом фильтре скрываются.
Переключение применяется сразу, сбрасывает страницу и сохраняется в браузере.

Источник — последний полный собственный скан. Частичный скан не заменяет предыдущий.
Межфракционные данные и оценки AHL не создают предложений в этом разделе.
Если минимальная цена принадлежит своему предложению, это отмечается в строке.

NPC-цена из самого лота имеет приоритет, включая ноль (предмет не принимают).
При отсутствии цены для базового предмета используется действующий справочник предметов/NPC.
Для особого варианта без своей NPC-цены подстановка базовой цены запрещена.
Сначала выбирается самый дешёвый вариант предмета; если его NPC-цена неизвестна или равна нулю,
предмет исключается. Более дорогое предложение вместо него не подставляется.
Объём предложения включает все варианты предмета, а NPC-цена относится к варианту с минимумом.
Бета-цена справочника отмечается. Старые сканы видны с предупреждением, если фильтр возраста равен нулю.

## Быстродействие веба

- Статус рынка берёт максимальную дату из исходной истории без лишней оконной сортировки.
- Игровые названия кешируются по ревизии на сервере и в пределах вкладки браузера.
- Статус, настройки и названия при запуске запрашиваются параллельно.
- Фоновая проверка названий не задерживает другие ответы API.
- Опрос статуса не накапливается, если предыдущий запрос ещё идёт; в скрытой вкладке приостанавливается.
- Большие ответы и статические ресурсы передаются с gzip при поддержке браузером.
- Веб получает готовые срезы через `view=true`; обновления выполняются отдельными потоками.
- Прогресс и опубликованные возможности читаются из SQLite без ожидания рыночной DuckDB.
- Анализ покрытия для разработки запускается при открытии настроек, а не при входе на сайт.
- Срезы сохраняются между перезапусками: максимум 32 файла по 2 МБ в `ui-views-v1`.
- При первом открытии ещё не подготовленного среза показывается загрузка; при обновлении остаются последние данные с датой.
- Операции закупки и публикации заданий выполняют прежние актуальные проверки, без кэша просмотра.
