# Cennik Worker — мост аукционера и крафтеров

Текущая версия: Worker 0.3.3 с CennikAddon 0.18.1. Большие очереди передаются
по одному снимку с отдельными подтверждениями; подробности —
[размеры и порядок обновления](CENNIK_RELEASE_SETUP.md).

В Worker 0.3.1 функция «Прыжок / Space…» адресно отправляет Space выбранному
фоновому окну WoW. Кнопка активации и маркер готовности аддона удалены.
Разовая отправка и повтор раз в три минуты включаются только в Worker.
Отправка сообщения не удостоверяет прыжок или сброс AFK самой игрой.

`dist/CennikWorker.exe` — отдельное приложение Windows x64 в трее, без необходимости
устанавливать Python. Вся аналитика, учёт и координация производства выполняются
полным Cennik Server. Worker передаёт приватные отчёты только своему серверу
и получает только назначенные ему персонажи. Collector для этого не подходит.

## Подключение

Начиная с Worker 0.2.0 можно подключить ПК по коду, выбрать роль каждого
персонажа кнопкой в аддоне и автоматически обнаружить оба аккаунта.
[Актуальный порядок и ограничения](CENNIK_RELEASE_SETUP.md).

Worker 0.2.1 исправляет регистрацию персонажей без профессий и вставку в поля
при русской раскладке: Ctrl+V, Shift+Insert и правый клик → «Вставить».
При HTTP 422 отчёт показывает этап обмена и имя проблемного поля, исключая
содержимое сохранений, токены и исходный текст ответа сервера.
Для обновления завершить прежний Worker через «Выход» в трее и запустить новый
EXE: существующие настройки и привязка ПК сохраняются.

Worker 0.2.2 восстанавливает подключение после отзыва ключа: оставить поле
ключа пустым и нажать «Сохранить и установить аддон». Если сохранённый ключ
отклонён с HTTP 401, приложение запросит новый код для одобрения владельцем
в вебе. Фоновые повторы не создают подключения. Ранее накопленные отчёты
сохраняются, старые маршруты отключаются. При явно введённом неверном ключе
показывается пояснение; для нового кода поле нужно очистить.

Владелец создаёт рабочий ПК в серверной панели, задаёт роли, персонажей, сервер
и при желании названия папок аккаунтов. Первый ключ рынка должен включать
аукционера; следующие могут включать только крафтеров. На одном ПК один ключ
может обслуживать несколько персонажей, в том числе разных аккаунтов.

1. Запустить Worker, выбрать папку игры с Auctionator.
2. Ввести адрес **корня** сервера `https://ваш-домен` и ключ Worker. Ключ владельца
   и ключ Collector здесь не подходят.
3. Нажать «Сохранить и установить аддон», при желании включить автозапуск.
4. Полностью перезапустить игру. Worker получит адресный импорт от сервера.
5. После `/reload` или входа аддон выберет маршрут по персонажу и имени сервера.
   Привязка подтверждённого сервером рынка выполняется автоматически. Для неизвестного
   аукциониста всё ещё требуется отдельное одобрение владельца.

Приложение находит стабильные сохранения по привязке персонажа и рынка. Общий
ImportedData.lua содержит отдельные маршруты для аукционера и каждого крафтера.
Крафтер не получает закупочные пакеты, снайпер или массовые задания аукционера.

Окно можно закрыть в трей; повторный запуск откроет существующее. Доступны пауза,
повторная отправка, диагностика и выход. Профиль по умолчанию находится в
`%LOCALAPPDATA%\CennikWorker`, автозапуск отделён от Cennik Collector.

## Что работает через сервер

- Публикация закупок и снайпера из веба → адресный импорт аукционеру.
- Массовая проверка → скан в аддоне → сохранение → расчёт на сервере → выбор
  выгодных результатов → обычные рабочие задания.
- Производственные заказы → задания крафтеру, передачи почтой/обменом,
  фактический крафт/распыление и возврат результатов.
- Финансовые события → серверный журнал, себестоимость и прибыль.
- Публичные наблюдения и подтверждения аукционистов → нужный сервер/рынок.

Отчёты хранятся локально до подтверждения обмена. При обрыве сети повторяется тот
же обмен, сервер не удваивает события. В приложении нет SQL-баз и локального
пересчёта стратегий. Worker не изменяет SavedVariables и не автоматизирует клики
в WoW. Загрузка задач и подтверждений игрой происходит после `/reload` или входа.

## Параллельная разработка и перенос привязки

Исследовательский Cennik и рабочий сервер используют разные базы. Для тестов
Worker выбирайте отдельную папку игры или отдельную установку аддона.
Worker откажется перезаписывать импорт, принадлежащий другому Cennik.

Если позже переносите действующую игру на сервер: сначала остановить локальную
синхронизацию Cennik; сохранить копии ImportedData.lua и SavedVariables;
переместить старый ImportedData.lua в резервную папку; затем подключить Worker
и установить аддон. Не запускать оба приложения на одной папке игры.
Это перенос привязки, а не автоматический перенос старых US-баз или финансового
журнала в новый рынок. История и неизвестные покупки не обнуляются молча.

Исходный запуск: `start_worker.cmd`. Сборка:

```powershell
$env:PYTHONPATH = "$PWD\src"
.\venv\Scripts\python.exe tools/build_collector.py --worker
```
