# Сборщики данных — CennikAddon 0.14.0

Сбор происходит при обычной игре. Аддон явно показывает своё состояние, приложение
сохраняет наблюдения и доставляет их отдельному приёмнику. Владелец видит участников,
количество принятых данных и сохранённые ошибки в разделе веба **«Сборщики»**.

Для аукциона требуется подтверждённый тип NPC. Любой участник предлагает его
в окне сборщика, владелец проверяет имя, ID, карту и координаты в вебе.
До одобрения сбор и закупки Cennik заблокированы. Межфракционный аукцион
сохраняется только в отдельный архив. [Подтверждение аукционистов](CENNIK_AUCTIONEERS.md).

## Что видно игроку

Под окном аукциона находится индикатор Cennik. Кнопка у миникарты открывает
самостоятельное окно, доступное также через **`/cennik collector`**.
В нём показаны текущая операция, причина ожидания, следующее действие, последний
полный снимок, строки и очередь, локальное подтверждение и последнее известное
подтверждение сервера с датой. Новый сбор можно приостановить.

Ошибки имеют постоянные коды: `SCAN_TIMEOUT`, `SCAN_INTERRUPTED`, `QUEUE_FULL`,
`SCAN_REJECTED`, `UNSUPPORTED` и другие. Игрок видит расшифровку и действие.
Повторяющееся состояние не спамит чат; отдельные повторные ошибки учитываются
счётчиком. Последняя ошибка и 20 переходов состояния сохраняются.

**`/cennik diagnostics`** или кнопка «Отчёт для поддержки» открывают выделенный
текст: Ctrl+C → отправить разработчику. Отчёт содержит ID сборщика, версии игры,
Cennik и Auctionator, рынок, состояния, очередь и коды ошибок. Пароли, токены,
имена персонажей, пути файлов и история покупок в него не включаются.

## Автоматический сбор

После открытия аукциона выдерживаются 3 секунды. Закрытие отменяет ожидание.
Если другой аддон запускает штатный полный `ReplicateItems`, Cennik подхватывает
тот же ответ. Повторный запрос не отправляется. Свой запрос выполняется через
Auctionator при свободном аукционе и готовности его API, с прежним интервалом
не менее 15 минут. Поиск, закупка, массовая проверка и снайпер имеют приоритет.
Пустые и незавершённые ответы не превращаются в полный снимок.

Дополнительно сохраняются наблюдения открытых NPC: ID/имя торговца, карта, предмет,
золотая цена упаковки, размер и доступный запас. Неподдерживаемые дополнительные
условия цены отмечаются как заблокированные, а не как бесплатный товар.
Открытая профессия даёт видимые рецепты и состав, если API его предоставляет.
Современный API без прочитанной схемы даёт только подтверждение изучения рецепта:
компоненты не выдумываются. У рецептов собственные даты наблюдения.
Фактические крафт и распыление дают наблюдаемые входы и выходы без финансового журнала.

У крафтера с отключённым автосканом AH пассивные наблюдения продолжаются при
включённой отправке. Для них нужен подтверждённый рынок. Отдельная пауза в окне
сборщика останавливает новый сбор. Уже сохранённая очередь приложения доставляется
независимо от паузы аддона; отправка отключается в вебе.

Сейчас поддерживается существующий рынок `forever.pvp.alliance.us`. Новый приёмник
архивирует исходные наблюдения, не подмешивает их автоматически в рабочую аналитику
и не складывает снимки разных игроков в доступный объём рынка. Пассивный сбор
результатов обычных точечных поисков ещё не добавлен.

## Граница автоматизации

Аддон накапливает данные в памяти. Игра записывает SavedVariables при `/reload`
или штатном выходе, а не при закрытии окна аукциона. Приложение не читает память
клиента, не нажимает кнопки и не выполняет автоматический reload.

После обычного сохранения игра → приложение → сервер работает автоматически при
включённых автоимпорте и отправке и запущенном приложении. Без дополнительных
действий игрока доставка произойдёт при его обычном выходе. Немедленная передача
из непрерывной игровой сессии этим файловым протоколом не обеспечивается.

ACK локального архива освобождает очередь аддона, серверный ACK — очередь доставки
приложения. Это разные подтверждения. После успешной отправки приложение обновляет
только метаданные доставки в ImportedData; следующий вход/reload покажет их в игре.
Отчёты NPC/преобразований очищаются только после явного локального ACK.
При заполнении очередей появляется видимая ошибка, новые наблюдения ограничиваются.

## Настройка участника

Для отдельного сборщика используйте **CennikCollector.exe**: выбор игры,
установка аддона, адрес и личный ключ, затем работа в трее без Python.
[Инструкция приложения](CENNIK_COLLECTOR_APP.md). В этом режиме недоступны
закупки и стратегии, финансовый журнал не записывается. Настройка ниже относится
к отправке наблюдений из полной версии Cennik.

Обновить аддон через настройки Cennik и полностью перезапустить игру: добавлены
Lua-файлы в TOC. Подтвердить рынок персонажа. В вебе открыть **«Сборщики» →
«Подключение сервера»**, указать адрес и личный ключ, включить отправку. Для
удалённого адреса требуется HTTPS; HTTP разрешён только для localhost.
Оставить автоимпорт сохранений включённым.

При недоступности сервера пакеты остаются на диске; повторные попытки откладываются.
Потерянное подтверждение не удваивает данные. Неверный формат сохраняется отдельно
в отклонённых. Ошибка ключа, сети, таймаута и неверного ACK показывается с причиной.
Ключи хранятся только в приложении; пустое поле сохраняет прежний ключ для того же
адреса. При смене адреса нужен новый ключ. В API чтения ключи не возвращаются.

## Отдельный приёмник и панель владельца

Приёмник использует новую явно указанную папку и JSON/zstd-архив. Он не открывает
рабочие базы Cennik, Docker/Compose не менялись. Запуск из окружения проекта:

```powershell
$env:CENNIK_COLLECTOR_ADMIN_KEY = '<отдельный случайный секрет минимум 32 символа>'
.\venv\Scripts\python.exe -m cennik.collector serve --root data/collector-hub
```

По умолчанию слушает только `127.0.0.1:8768`. Публичное размещение и HTTPS требуют
отдельной настройки инфраструктуры; действующий сервер этой работой не развёрнут.
Процесс должен быть один: запись архива сериализуется внутри него.

В своём Cennik указать адрес приёмника и **отдельный административный ключ**.
Он открывает таблицу участников, создание приглашений и отзыв доступа. Участнику
передаётся только его личный ключ загрузки. Первый ключ можно выпустить локально:

```powershell
.\venv\Scripts\python.exe -m cennik.collector invite --root data/collector-hub --label 'Участник'
```

Сервер хранит хеши личных ключей. Загрузочный ключ не даёт административный доступ.
Есть ограничения размера пакетов и частоты запросов. Повторы принимаются идемпотентно.
Проверка формата не доказывает правдивость наблюдения: архив сохраняет происхождение
по участникам, дальнейшая сверка качества остаётся отдельным этапом аналитики.

«На связи» означает свежий heartbeat приложения. В таблице отдельно показаны
последнее время наблюдения, полные/частичные сканы, строки, NPC, рецепты, крафт,
распыление и диагностика. Таблица обновляется в фоне, введённая форма не сбрасывается.

## Хранение и раздача

Локальные файлы — `data/cennik-next/collectors/`: `connection.json`, `local/`,
`outbox/`, `receipts/`, `rejected/`, `ack/`, `delivery.json`. Они входят в резервную
копию. **Connection и резервные копии содержат ключи: не включать их в раздачу.**
На сервере — `members/`, неизменные `raw/<kind>/*.json.zst` и подтверждения
`receipts/<member>/`. Счётчики восстанавливаются из подтверждений после сбоя.

Собран отдельный переносимый **CennikCollector.exe**. Python и аддон включены;
профиль и ключи не входят в раздачу. Публичный сервер и HTTPS ещё требуют
развёртывания, реальная совместимость API Forever — проверки в игре.
Браузерный тест двух изолированных HTTP-серверов: `tools/check_collectors_ui.py`;
проверка EXE и трея с настоящей доставкой: `tools/check_collector_desktop.py`.
