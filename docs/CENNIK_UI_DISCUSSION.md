# Предложения к обсуждению: карточка возможности и рынок

Дата: 22 октября 2026. Статус: записано для обсуждения, реализация не начата.
Пользователь попросил объяснить текущие действия и сохранить предложения.

## Запрошенные изменения

1. Показывать продажи/сутки сразу в карточке возможности рядом с капиталом,
   прибылью и ROI, без раскрытия подробностей. Для крафта это спрос на готовый
   результат. Подпись: «Оценка AHledger, последнее окно 7 дней». Неизвестное
   значение показывать как «нет данных», не заменять нулём. Показывать время
   данных источника; не выдавать время скана за отдельно известное время
   вычисления оценки продаж.
2. Из карточки готового товара, из материалов и промежуточных результатов
   цепочки открывать раздел «Рынок» сразу на выбранном item ID и текущем рынке.
   Предусмотреть понятный возврат в исходную возможность с сохранением партии.
3. В разделе «Рынок» дать ссылку на страницу предмета AHledger с выбранным
   рынком. Использовать канонический URL из ответа API, если он предоставлен;
   не строить английский slug из русского названия. Пример пользователя:
   https://ahledger.com/items/5763-red-woolen-bag.
4. В «Материалах и этапах крафта» показывать иконку, название, количество,
   источник покупки и стоимость; ID оставить вспомогательным идентификатором.
   Названия и иконки получать из доступного каталога/карточки предмета с кэшем.
   То же относится к промежуточным и готовым результатам CraftGraph.
5. Сделать назначение кнопок понятным до нажатия: подписи/пояснения должны
   различать загрузку справочных сведений, истории цен и расчёт закупки партии.
6. Объяснить бюджет и его происхождение. Текущие 30 золотых — значение профиля
   по умолчанию (300000 меди), не считанный баланс персонажа. Обсудить понятную
   подпись «Лимит закупки» и доступное изменение рядом с возможностями.

## Проверенное текущее поведение

- Продажи/сутки берутся главным образом из AHL1 pricetable: последнее поле
  salesPerDayX10 делится на 10. Дробные единицы в сутки допустимы.
- Это готовая оценка AHledger по последним семи дням, основанная на полных
  сканах. Не число завершённых продаж сегодня и не статистика за всё время.
  Исчезновение лота не всегда отличимо от снятия продавцом.
- «Рассчитать по объёму»: выбранная партия оценивается по предложениям
  сохранённого собственного полного скана, учитываются стеки, количество,
  возраст, бюджет и лимит партии по оценке спроса. Нового запроса WoW эта
  кнопка не делает. Для CraftGraph выбранный путь масштабируется; поиск
  оптимального альтернативного пути под партию не выполняется.
- «Обновить карточку»: запрос справочных свойств одного предмета
  GET /v1/items/{id}?game=forever. Не запускает новый скан аукциона и сам
  по себе не обновляет таблицу рыночных цен.
- «Подтянуть историю»: запрос цен выбранного предмета на выбранном рынке
  GET /v1/prices/{market}/{id}?range=7d. Сохраняются история и доступные
  последние сведения ответа. Это не выгрузка истории всего рынка.
- Запросы используют HTTP-кэш; нажатие не всегда означает новый сетевой GET.
  Пересчёт после новых данных зависит от настройки автопересчёта.
- Бюджет сейчас проверяет пригодность плана и ограничивает передачу, но не
  скрывает автоматически все дорогие возможности из предварительного списка.

## Первичные источники о метрике

- https://ahledger.com/developers — форматы pricetable, item, prices и поля продаж.
- https://ahledger.com/glossary — Auction house sales speed (liquidity): окно
  семь дней, оценка по исчезновению неистёкших лотов, ограничения метода.

Подробности оформления, подписи кнопок и управление бюджетом остаются на обсуждение.
