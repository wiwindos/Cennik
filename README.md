# AHledger Historical Downloader

Готовый CLI на Python 3.12+ для ручной исторической выгрузки экономики WoW Forever через публичные интерфейсы AHledger. Он сохраняет оригинальные ответы, очередь и прогресс, строит DuckDB/Parquet и показывает ограничения покрытия в HTML/JSON.

**Данные и цены: [AHledger](https://ahledger.com).** При показе полученных данных в собственном отчёте сохраняйте эту атрибуцию. Условия: https://ahledger.com/terms. Сканы не выдаются за собственные; перепродажа данных в виде feed не разрешена.

Полная историческая выгрузка при разработке **не запускалась**. На диске есть реальные ответы ограниченной разведки и отдельного smoke-test. Их объём и фактическое покрытие описывает `data/reports/download_report.html`.

## Docker и веб-панель на Ubuntu / Debian

При старте контейнера **ничего не скачивается из AHledger**. Откройте панель, введите секретный ключ, выберите рынки, типы данных и скорость, затем нажмите «Запустить / продолжить». Панель показывает очередь, записи, ошибки, текущие задания и ориентировочный срок. «Остановить» сохраняет прогресс; следующий ручной запуск продолжает очередь. После перезапуска контейнера прерванная загрузка не возобновляется автоматически.

На сервере нужны Docker Engine и Compose v2. После публикации проекта на GitHub:

```bash
git clone URL_ВАШЕГО_РЕПОЗИТОРИЯ ahledger
cd ahledger
cp .env.example .env
```

В `.env` задайте **публичный IPv4** сервера в `AHL_PUBLIC_IP` и случайный секрет в `AHL_WEB_API_KEY`. Секрет можно сгенерировать командой `openssl rand -hex 32`. `.env` и `data` исключены из Git и Docker build context. Этот секрет защищает вашу панель и API; это отдельный ключ, не ключ исходного AHledger API.

```bash
docker compose up -d --build
docker compose logs -f app gateway
```

Откройте `https://ВАШ_ПУБЛИЧНЫЙ_IP/`. TCP-порты **80 и 443** должны быть свободны и доступны извне, а IP должен быть назначен этому серверу. Сервис `gateway` использует Caddy 2.11.7 и явно выбирает ACME-профиль `shortlived` Let’s Encrypt для публичного IP. Сертификаты продлеваются автоматически и сохраняются в отдельном volume. Получение настоящего сертификата возможно только на вашем доступном из интернета сервере; локально оно не выполнялось. Подробнее: [IP-сертификаты Let’s Encrypt](https://letsencrypt.org/2026/01/15/6day-and-ip-general-availability), [профили ACME в Caddy](https://caddyserver.com/docs/caddyfile/directives/tls).

У приложения нет открытого наружу порта 8000: доступ идёт через HTTPS gateway. Панель публично показывает только экран входа; данные, журнал, API и все кнопки управления требуют `X-API-Key`. Ключ хранится в текущей вкладке браузера и удаляется при выходе. Одновременно допускается одно задание; веб-сервер запускается с одним worker.

Архив хранится в named volume `archive` (`/data` внутри контейнера). `docker compose down` и обновление образа сохраняют его. Команда `docker compose down -v` удаляет volumes вместе с архивом и сертификатами. Для резервной копии сначала остановите выполняемое задание в панели и контейнер приложения:

```bash
docker compose stop app
docker compose cp app:/data ./archive-backup
docker compose start app
```

Для восстановления остановите приложение, скопируйте содержимое резервной папки через `docker compose cp ./archive-backup/. app:/data`, затем запустите его. При переносе данных с Windows используйте весь каталог `data` после остановки локального загрузчика. Если UID файлов не соответствует UID 10001 внутри контейнера, исправьте владельца данных перед запуском приложения.

Обновление исходников и образа:

```bash
git pull
docker compose up -d --build
```

Перед обновлением остановите задание в панели. После обновления продолжение запускается вручную. История цен в панели/API читается из DuckDB после построения базы. База автоматически строится после завершения выбранной загрузки; после частичного прогона её можно построить отдельной кнопкой. Во время следующей загрузки API продолжает показывать предыдущую готовую базу, её дата видна в панели. Исходные ответы и очередь продолжают сохраняться независимо от построения базы.

Для локальной проверки контейнера без публичного сертификата:

```bash
docker compose -f compose.local.yaml up -d --build
```

Откройте `http://localhost:8000`. Вариант привязан к loopback и не публикует незашифрованную панель в интернете.

После публикации GitHub Actions выполняет Linux-тесты, сборку образа, проверку запуска без загрузки данных, проверку авторизации API и валидацию Caddyfile. Workflow не запрашивает данные AHledger и не получает реальные сертификаты. Локально Docker Engine был недоступен: конфигурации Compose, пакет, API и интерфейс проверены отдельно, а полный контейнерный тест выполняется в CI.

## Простой приватный API

Во всех запросах, кроме `/healthz` и экрана входа, передавайте заголовок `X-API-Key: ВАШ_СЕКРЕТ`.

| Метод и путь | Назначение |
|---|---|
| `GET /api/status` | Прогресс и состояние текущей задачи |
| `POST /api/jobs` | Ручной запуск `download`, `discover`, `build` или `verify` |
| `POST /api/jobs/stop` | Остановить задание с сохранением очереди |
| `GET /api/logs` | Последние 32 КБ журнала |
| `GET /api/items?q=cloth&limit=100&offset=0` | Поиск сохранённых предметов по названию или ID |
| `GET /api/prices/forever.pvp.horde.us/2589?granularity=hour&limit=500` | Сохранённые точки цены; `scan`, `hour`, `day`, цены в меди |
| `GET /api/files` | Готовая DuckDB, JSON-отчёты и последнее поколение Parquet |
| `GET /api/files/ahledger.duckdb` | Скачать готовую базу |
| `GET /api/openapi.json` | Схема API |

Пример тела `POST /api/jobs`:

```json
{"action":"download","markets":["forever.pvp.horde.us"],"datasets":["history","crafting"],"requests_per_second":2,"tools_per_second":0.5,"retry_failed":false}
```

Пустой `datasets` означает все типы данных; пустой `markets` — все обнаруженные рынки. Для выбранных типов автоматически добавляются необходимые справочники и каталог, для истории — таблицы цен, для рецептов — список профессий. Не выбранные задания остаются в очереди и не выполняются. API не принимает произвольные команды, SQL или URL. Максимум страницы — 1000 строк; отсутствующая аналитическая база возвращает HTTP 503, пустая история — пустой список реальных точек.

## Быстрый старт на Windows

В проекте уже подготовлено окружение `venv`. Из `C:\PythonProjects\Cennik`:

```powershell
.\venv\Scripts\python.exe -m ahledger download
```

Это команда **полной ручной загрузки**. По умолчанию она проверяет все обнаруженные каталожные ID на всех рынках, где подтверждена история, по четырём диапазонам, и дополняет каталог отдельными item-запросами. После неё создаются аналитическая база, Parquet и отчёт. На первый проход может потребоваться много часов; очередь растёт по мере обнаружения новых предметов.

Для установки с нуля:

```powershell
py -3.12 -m venv venv
.\venv\Scripts\python.exe -m pip install -e '.[dev,web]'
```

Точные версии, проверенные при разработке, сохранены в `requirements.lock.txt`:

```powershell
.\venv\Scripts\python.exe -m pip install -r requirements.lock.txt
.\venv\Scripts\python.exe -m pip install -e . --no-deps
```

На Linux команды аналогичны, путь к Python — `venv/bin/python`. Ключ публичному API не требуется. Если у вас есть read-only API key, передайте его через окружение (`$env:AHL_API_KEY = '...'`). Имя заголовка настраивается через `AHL_API_KEY_HEADER`, допустимы `X-API-Key` и `Authorization`; для последнего передайте полное значение, например `Bearer ...`, согласно инструкции к своему ключу. Авторизованный режим без предоставленного ключа не проверялся. `.env.example` описывает переменные; файл `.env` автоматически не читается.

## Команды и ограниченные проверки

```powershell
# Не обращается к сети и не создаёт очередь загрузки.
.\venv\Scripts\python.exe -m ahledger download --dry-run

# Только четыре запроса разведки. Очередь может быть подготовлена, но история не скачивается.
.\venv\Scripts\python.exe -m ahledger discover --max-seconds 45

# Построить/дополнить очередь по уже сохранённым справочникам, без сети.
.\venv\Scripts\python.exe -m ahledger plan

# Не более 10 попыток заданий и не более 30 секунд работы загрузчиков.
.\venv\Scripts\python.exe -m ahledger download --max-jobs 10 --max-seconds 30

# Продолжить после Ctrl+C, сбоя сети или перезапуска Windows.
.\venv\Scripts\python.exe -m ahledger resume

# Повторить задания, исчерпавшие лимит попыток.
.\venv\Scripts\python.exe -m ahledger resume --retry-failed

# Повторный ручной архивный проход; учитывает Cache-Control и ETag.
.\venv\Scripts\python.exe -m ahledger download --refresh

.\venv\Scripts\python.exe -m ahledger status
.\venv\Scripts\python.exe -m ahledger verify
.\venv\Scripts\python.exe -m ahledger report
.\venv\Scripts\python.exe -m ahledger export
```

`--max-jobs` считает попытки заданий, включая разведку и кеш. `--max-seconds` ограничивает сетевые workers; локальное планирование, построение базы и отчёт выполняются отдельно. Для быстрого остановленного прогона без построения базы добавьте `--no-build`, затем вручную выполните `build-db`, `verify`, `report`. Успешные задания сохраняются и при `resume` повторно не скачиваются. `--refresh` — явный новый проход, а не фоновый polling.

Общие параметры ставятся перед командой:

```powershell
.\venv\Scripts\python.exe -m ahledger --config config.toml --data-dir D:\AHledgerArchive download
```

Один рынок и другая скорость, без редактирования конфигурации:

```powershell
.\venv\Scripts\python.exe -m ahledger --market forever.pvp.horde.us --requests-per-second 2 download
# Продолжение с тем же выбором рынка и скорости:
.\venv\Scripts\python.exe -m ahledger --market forever.pvp.horde.us --requests-per-second 2 resume
```

`--market` ограничивает планирование и выполнение рыночных заданий, включая уже созданную очередь. Остальные рынки остаются в очереди; без флага загрузка снова охватывает все рынки. Общие справочники, каталог и карточки предметов скачиваются также при выборе одного рынка. Разведка содержит общую экономику всех рынков и запрос списка профессий через служебный endpoint. Флаг можно повторить для нескольких рынков. Постоянный выбор задаётся как `markets = ["forever.pvp.horde.us"]` в `config.toml`; чтобы снять его, верните `markets = []`.

`--requests-per-second` переопределяет глобальный лимит на текущий запуск (до 5). `--tools-per-second` отдельно переопределяет суммарный лимит market tools (до 1); без флага сохраняется значение конфигурации. Для продолжения передавайте те же флаги. Скорость означает максимальную частоту начала запросов; задержки сети и сохранённое снижение скорости после 429/503 могут уменьшать фактическую частоту. Все эти параметры ставятся **перед** `download` или `resume`.

`--dataset history --dataset crafting` ограничивает выполнение выбранными типами и необходимыми зависимостями, включая уже существующую очередь. Без `--dataset` скачиваются все типы. В веб-панели этому соответствует блок «Что скачать».

Пути и лимиты задаёт `config.toml`. Начальная скорость — 1 запрос/сек глобально, 0,5 запросов/сек суммарно к market tools. Документация указывает 300 запросов/мин глобально и 60/мин для market tools; наши значения консервативнее. После 429/503 скорость снижается, `Retry-After` сохраняется на диск и соблюдается после перезапуска. Повторные попытки используют exponential backoff с jitter.

`full_history_check = true` включает все ID из каталога, таблиц цен, рецептов, реагентов и других ответов. Рынки берутся из `/v1/markets`, наличие истории — из общей экономики и сохранённых проверок. Для рынков без сканов сохраняются метаданные и отдельная проверка пустой истории, без фиктивных цен. `enrich_items = "all"` оправдано тем, что компактный каталог не содержит vendorSell; `"referenced"` дополняет только предметы, встреченные в рыночных/рецептурных данных; `"none"` отключает дополнительные item-запросы.

## Что архивируется

Рынки; полные текущие таблицы AHL1; история каждого предмета за `24h`, `7d`, `30d`, `90d`; все опубликованные классы каталога; доступные item details; рецепты всех профессий с `all=1`; распыление с `all=true`; экономика всех рынков и дневные ряды; структура, сигналы и предложения; текстовый справочник `llms-full.txt`; RSS билдов; документы об API и условиях.

Для deals используются три сортировки при минимальных фильтрах, чтобы добавить разные top-N. Для signals используются только 12 значимых моделей (4 скидки × 3 горизонта), поскольку они меняют расчёт. Ни случайных комбинаций фильтров, ни перебора недокументированных путей нет. Tooltip дублирует уже получаемые цены/медианы/продажи, `/health` описывает эксплуатацию сервиса; они отмечены в реестре и не расходуют массовый бюджет загрузки.

Данные получаются через API. Единственная HTML-страница индекса каталога читается для обнаружения официальных классов и заявленных количеств; страницы предметов/NPC/рецептов массово не парсятся. Не используются игровые аддоны, upload endpoints, авторизация сторонних аккаунтов, торговля, планировщики, live polling, прогнозирование или бэктесты.

## Реальные ограничения источника

Исследование: `research/API_RESEARCH.md`. Реестр текущей выгрузки: `data/reports/source_registry.json`.

* `24h` — нерегулярные точки полного скана, а не фиксированные 15 минут. `7d` — часы, `30d/90d` — дни. Разница между формулировками документации записана в исследовании; формат подтверждён реальными ответами.
* AHL1 содержит 4 поля заголовка и 9 полей строки. `salesPerDayX10=4` означает оценку 0,4 единицы/день; обе формы сохраняются. Пустые поля остаются неизвестными.
* Каталог содержит 8 позиционных полей. Его четвёртая колонка — **подкласс**, класс берётся из категории. Остальные характеристики не выдумываются. Версия игрового билда не приходит в ответе каталога; `build_id` остаётся NULL, если источник её не сообщает.
* Crafting сообщает предел 500 записей на профессию. Результат, достигший этого предела, помечается PARTIAL. В опубликованной документации не найдено разрешённой пагинации или полной альтернативы; неизвестные параметры сервер игнорирует, поэтому добавлять выдуманный `page` нельзя.
* Disenchant ограничен 100 строками, structure — 60, deals — 200 на сортировку. `all=true` у распыления снимает фильтр прибыльности, но не ограничение количества. Сигналы — результаты правил, а не полный исторический архив рынка.
* Публичный bulk endpoint сырых отдельных аукционов не опубликован. `raw_auction_scans: unavailable`, запрос архива — https://ahledger.com/contact. Из медиан не создаются синтетические объявления.
* NPC, vendor inventory, дропы, зоны, квесты и полные исторические item/recipe diffs не представлены документированным bulk API. RSS содержит текстовые сводки билдов. `item_sources` остаётся пустой таблицей с отдельным статусом доступности.
* Оценка продаж не равна подтверждённым транзакциям. Агрегаты пригодны для исследований цен, но не позволяют достоверно моделировать исполнение сделок или исторический снайпинг.

COMPLETE в отдельном задании означает корректно полученный ответ для его заявленного диапазона/фильтра. PARTIAL отмечает пределы, пропуски, фильтрацию и незавершённую пагинацию. NO_DATA означает проверенный пустой ответ. NOT_AVAILABLE — недоступный endpoint/ресурс. FAILED — ошибку запроса/валидации. NOT_CHECKED означает отсутствие проверки, а не отсутствие данных у AHledger. Завершённая очередь не доказывает непрерывность датасета.

## Хранение и восстановление

```text
data/
  state.sqlite                 # очередь, кандидаты ID, HTTP-кеш, прогресс
  raw/blobs/ab/<sha256>.zst     # оригинальные HTTP-байты, content-addressed
  raw/metadata/<uuid>.json     # запрос, статус, SHA, timestamps, кеш и валидация
  logs/jobs.jsonl              # начало и результат каждого задания
  analytics/ahledger.duckdb    # нормализованная аналитическая база
  analytics/build_result.json
  parquet/CURRENT.json        # указатель на завершённую генерацию экспорта
  parquet/<generation>/*.parquet
  reports/download_report.html
  reports/download_report.json
  reports/verification.json
  reports/source_registry.json
  smoke/                      # отдельный архив сетевого smoke-test
```

Один и тот же набор исходных байтов хранится один раз; разные HTTP-запросы имеют разные метаданные, даже если тела совпали. Для 304 сохраняются его пустое исходное тело и ссылка на предыдущие байты. API-ключи, cookies и секретные заголовки исключены из метаданных и логов. Запись идёт через временный файл, fsync и замену в том же каталоге. Один архив допускает только одного writer; ОС освобождает блокировку при аварии.

DuckDB и Parquet полностью восстанавливаются из raw без сети:

```powershell
.\venv\Scripts\python.exe -m ahledger build-db
.\venv\Scripts\python.exe -m ahledger verify
.\venv\Scripts\python.exe -m ahledger report

# Если SQLite потерян: восстановить завершённые задания и справочники из manifest.
.\venv\Scripts\python.exe -m ahledger build-db --restore-state
.\venv\Scripts\python.exe -m ahledger resume
```

После восстановления SQLite несохранённые pending-задания заново строятся из справочников при следующем `download/resume`. Не удаляйте raw: это единственный первичный архив. При разборе неожиданных полей они сохраняются в raw и `payload_json`; изменение формы схемы отмечается в метаданных. Повреждённые ответы не становятся наблюдениями.

## Схема и семантика аналитики

* `price_history_ranges` сохраняет наблюдения каждого диапазона отдельно. `price_history` удаляет только дубликаты одинаковых рынка, ID, времени и детализации; выбирается самый свежий ответ, при равном времени совпавшие дневные 30d/90d имеют приоритет 90d. Часовая и дневная точки всегда различаются.
* `preferred_price_history` выбирает точки по сканам вместо часового агрегата покрытого часа, а часовые/скановые точки вместо дневного агрегата покрытого дня. Это выбор исходной детализации, **не пересчёт** дневного агрегата и не доказательство полного покрытия дня. Для проверки пробелов используйте базовые таблицы.
* `price_snapshots` хранит таблицы AHL1 и latest из history. Top-level sales относятся к моменту запроса; они не приписываются старым историческим точкам.
* `recipes` и `recipe_inputs` — описания механики и версии состава. `recipe_valuations` — отдельные рыночные оценки с pricesAsOf/generatedAt и ценами реагентов в payload. Аналогично разделены `disenchant` и `disenchant_mechanics`.
* `markets`, `items`, `item_versions`, `market_economy`, `market_deals`, `market_signals`, `market_structure`, `item_sources`, `build_changes`, `dataset_metadata`, `download_jobs`, `coverage`, `source_availability` доступны непосредственно в DuckDB и Parquet.

Время нормализовано в UTC. В SQL выполните `SET TimeZone='UTC'`, чтобы вывод TIMESTAMPTZ не зависел от настроек компьютера. Сами TIMESTAMPTZ хранят абсолютное время.

Наблюдаемые цены — целые int64 copper. API иногда отдаёт дробную расчётную netValue/margin/base: исходное Decimal-представление сохранено в raw/payload и специальных `*_exact_copper` строках, нормализованное `*_copper` — целое с округлением вниз. Эти величины отмечены как оценки. Дроби не превращаются в бинарный float для денежных расчётов. Неизвестные значения остаются NULL, а не нулями.

Часть `items` — явно отмеченные `is_placeholder` ID из прайс-листа, пока детальная очередь не обработана. Это обеспечивает ссылочную целостность без придуманных названий и характеристик. Версии предметов представляют реально сохранённые ответы, а не восстановленные задним числом старые билды.

## Читать реальные данные в Python

```python
import json
from pathlib import Path
import duckdb

root = Path('data')
db = duckdb.connect(str(root / 'analytics/ahledger.duckdb'), read_only=True)
db.execute("SET TimeZone='UTC'")
print(db.execute("""
    SELECT market, granularity, MIN(observed_at), MAX(observed_at), COUNT(*)
    FROM price_history
    GROUP BY market, granularity
    ORDER BY market, granularity
""").fetchall())

generation = json.loads((root / 'parquet/CURRENT.json').read_text('utf-8'))['directory']
parquet = root / 'parquet' / generation / 'price_history.parquet'
print(db.execute('SELECT COUNT(*) FROM read_parquet(?)', [str(parquet)]).fetchone())
db.close()
```

SQL для уже сохранённого реального Linen Cloth:

```sql
SET TimeZone='UTC';
SELECT observed_at, granularity, min_copper, median_copper, quantity
FROM price_history
WHERE market='forever.pvp.horde.us' AND item_id=2589
ORDER BY observed_at, granularity;
```

## Тесты и диагностика

```powershell
# Без сети, mock HTTP; занимает секунды.
.\venv\Scripts\python.exe -m pytest -q
.\venv\Scripts\python.exe -m ruff check src tests tools
.\venv\Scripts\python.exe -m mypy src\ahledger

# Явно сетевой: максимум 6 запросов, жёсткий предел времени, без расширения очереди.
.\venv\Scripts\python.exe -m ahledger smoke-test --max-seconds 25
```

Проверяются кеш/304, 429/503/Retry-After, разрыв сети, отсутствующие/неожиданные поля, JSON/формат AHL1, цены/UTC, дедупликация, пропуски, лимиты, восстановление, Ctrl+C/тайм-бюджет, атомарная запись и Windows-блокировка. Smoke-test архивируется отдельно; его результаты не добавляются к основному отчёту автоматически.

* **429/503:** дайте очереди дождаться Retry-After, не увеличивайте скорость. `--max-seconds` позволяет безопасно остановить ожидание и продолжить позже.
* **FAILED:** посмотрите `logs/jobs.jsonl`, `status`, raw manifest. После восстановления сети используйте `resume --retry-failed`. При изменении API обновите парсер; raw остаётся пригодным для повторного разбора.
* **Another writer:** другой запуск работает с той же папкой. Статус можно читать, второй writer не запускайте. Не удаляйте lock-файл вручную.
* **DuckDB PermissionError на Windows:** закройте подключения к старой базе, прежде чем заменять её через `build-db`.
* **SHA/повреждённый Zstandard:** `verify` завершится ненулевым кодом. Восстановите blob из резервной копии или скачайте ресурс повторно. Сохранённая manifest-ссылка показывает точный источник.
* **Отчёт PARTIAL:** посмотрите coverage, ограничения источника и незавершённые задания. Отсутствие строки в сегодняшнем прайс-листе не исключает предмет из полного исторического прохода.
* **Место на диске:** поколения Parquet сохраняются для безопасного переключения; старые можно вручную удалить, сохранив каталог из `CURRENT.json`. Сделайте резервную копию `raw` и `state.sqlite`.
